React Frontend Sequence Diagram

These sequences show how the React application boots, restores state from localStorage, loads market and chart data, coordinates the CoinDCX trading dashboard, and inspects backend WebSocket activity. The flows are based on the current page and context implementations in the frontend codebase.

App shell, market data, trading flow,
and WebSocket monitoring

1. App Bootstrap And Login Flow

App startup restores stored API credentials, routes the user, and lets LoginPage write fresh credentials back through AuthContext.

100%

Drag inside the diagram to pan. Use Ctrl + mouse wheel to zoom at the pointer.

4. WebSocket Monitor Flow

WebSocketPage polls connection status, lets the user inspect captured event messages, and clears per-event or global message buffers through backend REST endpoints.

100%

Drag inside the diagram to pan. Use Ctrl + mouse wheel to zoom at the pointer.

sequenceDiagram autonumber actor User participant Monitor as WebSocketPage participant Api as apiService participant Client as apiClient participant Backend as Spring Boot API User->>Monitor: Open WebSocketPage Monitor->>Api: getWebSocketStatus() Api->>Client: GET /api/websocket/status Client->>Backend: fetch connection state and storage stats Backend-->>Client: status, subscribedChannels, storageStats Client-->>Api: response Api-->>Monitor: status payload Monitor-->>User: Render connection card, storage stats, channel list Note over Monitor: useEffect refreshes status every 10 seconds User->>Monitor: Select event type Monitor->>Api: getWebSocketMessages(selectedEvent) Api->>Client: GET /api/websocket/messages?event=... Client->>Backend: fetch captured message buffer Backend-->>Client: messages[] Client-->>Api: response Api-->>Monitor: messages payload Monitor-->>User: Render up to first 50 messages alt Clear one event buffer User->>Monitor: Click Clear for selected event Monitor->>Api: clearWebSocketMessages(event) Api->>Client: DELETE /api/websocket/messages/clear?event=... Client->>Backend: clear event buffer Backend-->>Client: success Monitor-->>User: Empty message list else Clear all message buffers User->>Monitor: Click Clear All Monitor->>Api: clearAllWebSocketMessages() Api->>Client: DELETE /api/websocket/messages/clear-all Client->>Backend: clear all message buffers Backend-->>Client: success Monitor-->>User: Reset selected event and messages end
